# 对战策略与陪练实验调研

2026-11-25

我们有两个不同的验收目标。终极档陪练要复现官网人机在同类局面下的反应，包括它会犯的错。参赛策略要在官网计分下更强。一个陪练更难打，或者能把一局拖到 90 秒，都不足以说明第一项目标有进展。

## 三个优先实验

### 1. 先校准我们判断“像不像”的尺子

从一个有源码的本地策略生成回放，隐藏其身份，用同策略复跑作对照。再分别让它晚两帧开火、稍晚撤退，一次只改一个动作。开火指标应当能分出前一种改动，撤退指标应当能分出后一种。若一个改动只在整局时长上显眼，先看短窗口指标是否漏掉了触发点。

官网同图、同策略、同侧、同局号的 16 对重复练习里，时长差绝对值的中位数为 4.85 秒，2 对连赢家都变了。这给出了当前条件下的重复波动，包含联机时序等影响。对稀有行为同时报涉及多少张图、出现多少局。比较版本时对同一张图做配对，再按地图汇总和估计区间。研发用过的图留在开发集，换版时另用未参与挑选的新图。[定向练习方案](./在线采样.md) · [小样本评估方法与代码](https://github.com/google-research/rliable)

### 2. 用同一个接战片段区分三种失败

首选“第一次近身后何时拉开”，同时保留近身后一直没拉开的局。只从成功撤退的回放截片段，会漏掉模型过早撤退的错误。用已有 SDK 分支从首次进入同一距离带的前一帧起跑，给各版本相同的可见历史，先固定对侧的回放动作，再让冻结的对侧策略自由响应。

| 观察结果 | 优先查什么 |
|---|---|
| 把官网双方反推的动作送回 SDK，短时间内就偏离官网 | 查起始状态、帧序和动作标签。贴墙不动有时分不清刹车还是继续推墙，训练端已有缺失标签，诊断时也要保留这种不确定性。 |
| SDK 能复演；陪练的所有候选都在靠近，官网却在主动退 | 查是否缺少这种局面，以及候选能否表达“转向后倒退”等连续动作。现有轨迹版用前 3 帧持续转向、随后直行来估计候选路线。 |
| 候选里有接近官网的路线，实际输出却走了另一条 | 查候选排序和控制分支。现有轨迹版只在当帧决定不开火时调整走位，可单独统计“准备开火”和“未准备开火”两组。 |

短窗口同时记官网与陪练有没有撤、多久开始撤、哪方贡献了距离变化。两者都撤了才计算时机差，漏撤和多撤单列。短窗口里固定对侧动作能定位第一处偏差；换一种动作会不会诱发官网人机另一种反应，要靠真实练习验证。仓库已经有分支复跑、进退反推和同图开火／停火探针，可以复用。[短程复跑](../training/evaluate_boss_behavior.py) · [动作反推](../training/fit_boss_sparring.py) · [轨迹版决策](../training/boss_trajectory.py) · [有针对性的干预为何有辨识力](https://proceedings.neurips.cc/paper/2019/hash/947018640bf36a2bb609d3557a285329-Abstract.html)

### 3. 采能区分两种解释的数据

例如我们观察到官网人机会在近身时横移，有两种解释：它响应来弹，或者它本来就会在这个距离横移。沿用同一导航、地图和出生侧，在预先约定的接近窗口里，一组开火、一组停火。按开火前距离、双方朝向和可用退路比较，只看策略开始分歧后的短窗口。停火组也从同一个满足开火条件的时刻起算。同图重复、交换红蓝；若两组进入窗口时的局面相差很大，这组只计覆盖，不能据此归因。

两组反应明显不同，下一轮优先补“看到弹后多久、往哪边移动”；两组近似，就去切分靠墙、圈边或距离条件。低命中练习只要制造了真实躲弹，仍有学习价值；要学中弹后的反应，则单看这些练习不够。[已有采样对照](./在线采样.md) · [观察轨迹下的行为克隆](https://www.ijcai.org/Proceedings/2018/0687.pdf)

## 参赛策略该优先优化什么

先分清是**没创造机会、错过机会，还是出手判断错了**。例如面对同一档人机，分别记录进入可交战位置的次数、每局命中数、承伤和官方分项。很少进入合适位置就先改走位；机会多且多数出手落空再改预测。只挑最容易的几发打，可以抬高命中率，同时降低得分。种子杯的伤害分单局封顶 50，剩余生命和提前结束时间另计，候选最终仍用官方计分比较。[官网规则](https://tank.dian.org.cn/docs#rules)

固定计算预算，把当前规则动作作为基线，再分别改变“考虑几种对手反应”和“向后推演多长时间”。官网能核验的是实际采取动作后的结果，另一种动作在同一段录像上的得分只是回顾性估计。待陪练在关键反应上通过独立验收，再用它筛选参赛策略；官网练习负责确认收益。Halite III 冠军也报告过，把规划延到下一处资源点没有带来收益，规划深度值得当成实验变量。[Halite III 冠军复盘与实现](https://github.com/teccles-halite/halite3-bot) · [现有专项试射](../strategies/boss-specialist/boss_local_aim.py)
