# 双线自动训练

人机复测结案后，双方版本的对局都进入后续轮次的训练池。训练按失分局面挑图换边重打，下一轮官网复测另选新图。

主号训练能赢 BO11 的策略，副号比较能提高四档总分的策略。两条线各有现役、候选和轮次。总榜使用天梯现役自身的正式人机分，独立人机主力可以刷新队伍的人机历史榜。

| 阶段 | 天梯 | 人机 |
|---|---|---|
| 采集 | 主动和被动系列赛按官方 ID 归档。每四次主动挑战，三次争取升位，一次补陌生或难打的对手。双方自有账号互相排除。 | 持续终极档同图换边。原任务接着采，旧地图保留当时的参赛快照。准备选优时，副号优先执行定向对照，队友练习优先。 |
| 本地选优 | 首轮从走位切换 v2 搜索，对照官网当前天梯版本。候选和现役在相同冻结对手、地图和随机条件打 BO11。胜局数相同按实际累计伤害裁决。 | 从已有切换策略和专项出发，使用官方新手和本地终极陪练 v31 做初筛。记录每局四项得分和双方换血。 |
| 官网门槛 | 每种打法至少 8 组配对系列赛，交替首局出生侧。分组重采样的胜率差 95% 区间下界大于零，才提交主号正式 40 局。达到 4333 分后选择待生效版本，主动对战，核对官网生效记录。 | 终极档五张新图，两版各打红蓝两侧；按地图配对的每局增分 95% 区间下界大于零，才补其余三档。四档等权的 40 局增分区间下界大于零才提交主号正式评测。正式总分提高才更换人机主力。 |
| 上线复盘 | 新旧版都打过的对手分组比较。新版至少 12 场可比系列赛、覆盖 4 队且胜率差区间上界小于零，才切回上一主力。 | 官网完整成绩归到提交快照，人机线仅办理评测。 |

## 旧数据与经验

同一场的原始回放和 SDK 观测按官方对局 ID 合并。版本待核实的对局保留行为证据。经验报告提取首次交手、连续落空、换血、脱离交火、缩圈失位。每项附对局、时刻、选择和后果。回放上的推断用新对局验证。

训练图与验收图按布局隔离，天梯保留完整系列赛与对手分组。一次跨线实验只借一个能力，在接收方现役上与原版配对。每轮保留参数和逐局成绩；相同搜索范围连续三轮未晋升后，采集继续，搜索等新打法。对手池与分布偏差的设计分别借鉴 [AlphaStar 联赛训练](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/) 和[离线强化学习研究](https://arxiv.org/abs/1812.02900)。

首轮历史能力试验按单局记录，只作为下一轮搜索的建议。新的人机能力迁入天梯时，以 BO11 系列赛配对验证；正式天梯换版还要通过整版验收。缺少可核实的天梯现役时，人机线照常训练，借用试验临时以走位切换 v2 作本地对照。

## 给 GPT 的入口

| 命令或文件 | 用途 |
|---|---|
| `tank cycle start all --json` | 在共享练习主机启用两条线，包括通过门槛后的官网操作。可指定 `pvp` 或 `pve`。 |
| `tank cycle status all --json` | 查看现役、候选、轮次、阶段、采样任务及最近错误。 |
| `tank cycle pause pve --json` / `tank cycle resume pve --json` | 单独暂停、从上一个已保存的训练分组或采样格继续。官网已受理的对战或评测按官网进度结算。 |
| `tank cycle report all --json --since <上次 as_of>` | 读取增量经验、代表回放和晋升历史。首次省略 `--since`。 |
| `tank cycle reconcile --json` | 核对天梯请求是否已由官网受理。结果长期不明时，复核后用 `--clear challenge` 或 `--clear activation` 解除相应的本地等待。 |
| `.local/cycle/<pvp或pve>/rounds/<六位轮次>/` | `plan.json` 冻结参赛快照与实验条件，`result.json` 记录成绩、置信区间与跨线实验。 |
| `.local/cycle/ladder/` | 系列赛、逐局归属、完整回放及待核实的官网操作。 |
| `.local/cycle/profile.json` | 2、4、8、12、16 个进程的实测吞吐和同期 SDK 动作记录；对局量不足的档位保留观测状态。 |

官方口径以[比赛规则](https://tank.dian.org.cn/docs#rules)为准。
