# 终极档陪练的走位与躲弹

## 为什么旧陪练约 20 秒就输

三版游击策略在地图 8107、44917 各换边一次。每场用同一策略快照、地图、出生侧和局号在 SDK 复跑。比较开局时，两份回放都截到较短一局结束。

| 12 场游击对局 | 官网终极档 | 旧陪练 |
|---|---:|---:|
| 整局时长中位数 | 90.0 秒 | 20.5 秒 |
| 首次互相可见中位数 | 2.15 秒 | 3.40 秒 |
| 相同开局内，陪练被击中的局数 | 2/12 | 12/12 |
| 双方最近距离中位数 | 2.47 格 | 0.96 格 |
| 我方命中率中位数 | 0% | 91% |
| 陪练连续中弹次数中位数（相邻命中相隔 ≤2 秒） | 0 | 9 |

旧陪练通常在第一次贴近后被连续击中。它在 12 局里首次中弹的中位数为 3.9 秒。官网两次分别在 14.3、17.3 秒，其余十场在对应开局里均未中弹。回放还能看出开火前后的横移差异。以我方每次开火时的朝向为基准，截取前后各半秒，计算垂直于射线的净位移速度，先取局内中位数，再取 12 局中位数。官网人机从 0.18 变为 0.45 格/秒，旧陪练从 0.34 变为 0.16 格/秒。

在开发图 96671 的两场对局里，把旧陪练直接放回官网遇弹前的同一位置、朝向和场上弹道。按 SDK 的离散碰撞规则识别出 33 次可归因的危险来弹。官网实际中 2 次，旧陪练中 30 次。把反推的官网动作交还给 SDK，33 次命中与躲过均对得上。这说明即使消除前面走位累积的差异，旧陪练依旧躲不开这些来弹。

## 采样与训练

使用种子杯 0.4.3 的正式规则。回放提供位置、朝向、射击计数和弹道。训练从连续两帧反推进退、转向和开火，碰墙而无法区分进退的帧不计算进退损失。整局按地图分组，每次加入一批后重新训练。开发图 96671 看游击，715121 看接近与倒车，两图等权比较危险来弹的逐弹命中一致率，一致率相同时取半秒走位平均误差小的模型。两图均不用于拟合。无法追溯我方快照的历史场次不参与整局重演。

每个主动采样批次使用两张图，每种打法各换边一次。下表为官网终极档每种打法 4 局的时长中位数。第一批的开火、停火两组，终极人机都取得了 40 次命中。

| 地图种子 | 打法一 | 打法二 |
|---|---|---|
| 712101、712117 | 接近开火 · 19.4 秒 | 同样接近但停火 · 19.3 秒 |
| 713029、713053 | 接近开火 · 18.1 秒 | 面朝对手倒车开火 · 30.0 秒 |
| 714079、714091 | 游击 · 67.5 秒 | 面朝对手倒车开火 · 25.5 秒 |

旧模型把转向拟合为一个连续值。开发集里约 55% 的真实动作打到接近满舵，旧模型只给出约 11%。新版同时预测进退和五档转向，在选中档位内预测具体幅度，并利用最近两秒的运动。这个做法借鉴了多种合理动作共存时先分档再拟合偏差的思路。[BeT 原论文](https://arxiv.org/abs/2206.11251)

为了处理画面中已经出现的来弹，模型先用 SDK 试走自己选的动作。仅当眼前炮弹会打中且当前动作躲不开时，才试其他进退、转向组合，选能躲开且最接近原动作的一组。这个半秒预测假定对手暂时停在原位。

共训练到 58 场、29,002 帧。已有 27 场作为起点，补回历史练习 4 场再加 3 场，之后每次加入 8 场主动采样。仅在开发图上选模后冻结 31 场版，两张开发图上的真实来弹分别为 33 次和 23 次。31 与 58 场版对同一颗弹的判断都只错 1 次，31 场版的半秒位置误差更小。

|---:|---:|---:|

| 34 | 94.80% | 0.672 格 |
| 42 | 96.97% | 0.605 格 |

## 复现

先启动[共享练习主机](./在线采样.md)。复采本实验的原始方案用 `.\.venv\Scripts\python -B training/collect_boss_behavior.py fire distance roaming dev test`。同批复跑会复用已保存的地图和出生侧。默认导航使用游击初版；其他机器可用 `--lancer <游击快照 ID>` 选择提供相同导航接口的快照。批次清单在 `.local/behavior/batch-*.json`，原始回放在 `.local/online/replays/<对局编号>.json.gz`。

走位验证每秒取一个起点，用最多两秒的回放预热模型，再用 SDK 推进 0.5、1、2 秒。我方运动跟随原回放，陪练根据自己的新位置重新决策。躲弹验证按独立炮弹计数，挑出已出现在观测中、保持原地会在半秒内被击中的炮弹。另用双方各自决策的整局 SDK 复跑检查时长。位置误差单位为地图格。

新电脑可将[实验数据包](../published/datasets/boss-behavior-20261125.zip)解压至 `.local/`，内含 77 场公开回放、换边记录、采样策略及阶段模型。[分组清单](../published/datasets/boss-behavior-20261125.json)列出每场用途及文件哈希。复算盲测无需登录官网。

```powershell
$data = Get-Content -Raw published/datasets/boss-behavior-20261125.json | ConvertFrom-Json
$model = (.\.venv\Scripts\tank.exe snapshot create --strategy boss-sparring --json | ConvertFrom-Json).id
$ids = $data.blind
.\.venv\Scripts\python -B training/evaluate_boss_behavior.py trajectories --models $data.initial_model $model --ids @ids --require-unseen --calibrate --output .local/behavior/recheck.json
```

从现有训练作业加入一批回放时，运行 `training/fit-boss-batch.ps1 -PreviousJob <作业ID> -Batch .local/behavior/batch-fire.json`。新作业记录基础配置、训练回放、开发回放和导出的快照 ID。

## 交战距离训练

同一批回放先用 `maneuver-evasion` 训练逐帧动作对照组，再用 `range-evasion` 加入距离预测。两个模型使用相同动作网络、初始化、训练顺序和躲弹逻辑。后者每帧还学习预测接下来 1 秒、3 秒双方距离的变化。标签由同一局回放计算，局尾不足指定时长的标签跳过。预测所用的信息都来自当前及过去帧；导出陪练时删去距离预测层。

这个设计借鉴了从演示片段的未来状态构造监督信号的做法。种子杯没有选手指定的目标位置，因此用实际距离变化作辅助目标。它可能让网络更容易分辨追击和脱离；是否改善以陪练自行决策时的整局结果为准。[Learning Latent Plans from Play](https://proceedings.mlr.press/v100/lynch20a.html)

```powershell
./training/fit-boss-batch.ps1 -PreviousJob <作业ID> -Modes range-evasion -RangeWeight 1
```

### 选模与新图验证

固定训练回放、开发地图和两张待验证的新图。开发时按相同策略快照、地图、局号和出生侧复跑。交战距离只比较官网和所有参评版本都存活的同一段时间，时长和死亡结果按整局统计。先在每张图内对各打法等权，再对地图等权。逐局结果和比较窗口长度都在报告中。

候选须同时满足四项条件：交战距离中位数的误差减小，时长平均误差及陪练死亡判断错误率均未增加，任何单个打法的时长平均误差最多增加 5 秒。5 秒是本队的选模容差。开发报告确定一个版本后，用相同准则对它与现用版本做新图验证。新图通过后才更换默认陪练。

```powershell
python training/select_boss_behavior.py --baseline <现用快照> --models <候选快照> --ids <开发对局ID列表> --output .local/behavior/dev.json
python training/select_boss_behavior.py --baseline <现用快照> --models <已选快照> --ids <新图对局ID列表> --development-report .local/behavior/dev.json --output .local/behavior/final.json
```

同一策略和地图需提供成对的红蓝回放。`--development-report` 锁定开发阶段选出的版本，并排除训练、留出及整局选模用过的地图种子和布局。单独诊断某个版本时可用 `--require-unseen` 排除训练与留出地图。

### 2026-11-25 对照结果

在 35 张训练地图的 170 场回放上固定网络、采样顺序和 36 个训练轮次。开发集为 5 张图、24 局，含同侧和换侧的游击、接近、撤退等打法。下表四个版本在同一次整局复跑中比较。

| 陪练 | 交战距离误差（格） | 时长误差（秒） | 死亡判断错误率（地图等权） |
|---|---:|---:|---:|
| 当前默认，31 场训练 | 2.32 | 6.40 | 3.3% |
| 原训练方法，170 场 | 3.44 | 14.10 | 13.3% |
| 距离预测权重 1，170 场 | 2.24 | 9.46 | 10.0% |
| 距离预测权重 4，170 场 | 3.46 | 9.89 | 13.3% |

在原有 31 场回放上加入权重 1 的距离预测，开发集时长误差为 14.27 秒。另测了 `-BalanceMaps`：先使每种地图布局的训练帧总权重相同，再让同图各场等权。此批 170 场中，帧数最多的 5 张图占了全部训练帧的 33.7%。等权版与默认版单独配对时，交战距离误差为 3.51 对 2.32 格，时长误差为 9.21 对 6.40 秒。所有候选均未达到换版条件。

用预留的地图 903833105、903937834 做独立诊断，两图共 12 局。默认陪练与权重 1 候选的距离误差分别为 1.48、2.98 格，时长误差分别为 4.73、12.35 秒。在探头打法的两局中，官网终极人机的交战距离中位数分别为 7.7 和 6.4 格，候选均为 2.2 格。新图包含 14 次可追踪的实际中弹。精确比较可按实验目录中的 `plan.json`、`freeze.json`、`dev-fair.json` 和 `final-games.json` 复核。本机实验目录为 `.local/behavior/boss-range-20261125-171254/`。

### 起步停滞与缩圈退让
